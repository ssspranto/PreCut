# AGENTS.md

Windows-only Python desktop app (CustomTkinter + `yt_dlp`) with 5 sidebar pages. No web backend, no database, no tests.

## Commands

- Run app: `python src/main.py` (from repo root). Pages are imported as top-level modules (`from page_clips import ClipsDownloader`) — that only works because running `src/main.py` puts `src/` on `sys.path`. Add new modules to `src/` and import them the same way.
- Build portable exe: `python build.py` (clean) or `python build.py --fast` (rebuild only). Requires PyInstaller installed.
- There are **no** tests, linters, or type checkers configured. Verify changes by running the app manually. Only `pip install -r requirements.txt` (customtkinter, Pillow, yt-dlp, requests) is needed to run.

## Architecture

- `src/main.py` is the entrypoint; it builds the sidebar and registers pages via `ServicesView.add_page(image_path, service_name, page)` (main.py:203). A new feature = new `src/page_*.py` + one `add_page` call.
- Each page is a `Page` subclass from `src/ui_page.py:9` (a `ctk.CTkFrame`). Download pages use `DownloadCard`/`DownloadingPanel` from `src/components.py` and pull format selectors from `src/config.py`.
- `src/utils.py:get_asset_path()` resolves `assets/...` for both dev and PyInstaller `_MEIPASS`; always get paths through it.
- All `yt_dlp` calls go through the Python API (threads in `components.py`), never subprocess; `ui_page.py:apply_cookie_option()` builds cookie/EJS opts.

## Concurrency rule (important)

Each download page keeps `self.active_downloads` and rejects duplicate URLs and rejects when `len(...) >= 2` — max **2 concurrent downloads per page** (page_clips.py:91-95, same in proxy/ost). Any new download page must replicate this pattern.

## Config / state lives outside the repo

- `src/config.py` reads/writes `~/Documents/PreCut/data/settings.json` and exposes a module-level singleton `app_config` (import `from config import app_config`). It auto-regenerates `format_commands` from templates on every startup (`regenerate_all_commands`).
- `sys.pycache_prefix` redirects all `__pycache__` to `~/Documents/PreCut/data/pycache` (main.py:5). Do not create `__pycache__` inside `src/`; if you see `build/` or `dist/` in the working tree they are stale local artifacts and are gitignored.

## Format templates

Format commands in `config.py` are assembled from `QUALITY_FORMAT_TEMPLATES` + `CODEC_OPTIONS` + `AUDIO_FORMAT_OPTIONS`. The `{codec}` placeholder has a quirk: templates include `[{codec}]` brackets and the code adds/removes them (config.py:93). If you touch these templates, run the app and check Settings → downloader page output.

## Packaging / release

- `PreCut.spec` is **generated by `build.py` and gitignored** — never hand-edit or commit it; `build.py` deletes it on clean builds. PyInstaller flags that matter: `--onefile`, `--windowed`, `--collect-all=customtkinter`, `--collect-data=yt_dlp`.
- Version is stamped in two places: `version_info.txt` (PyInstaller version resource, currently 2.1.0.0) and the hard-coded `"PRECUT 2.0"` sidebar logo / `"PreCut 2.0 - ..."` window title (main.py:141,180). Bump all of them on release.
- Releases are cut by pushing a `v*` tag; `.github/workflows/release.yml` builds on Windows with Python 3.12 via `python build.py`, then `installer.iss` (Inno Setup). Release notes go in `docs/v<major>.<minor>.<patch>_release_notes.md` and CHANGELOG.md.
- FFmpeg must be on `PATH` for format merging (warned at startup via `check_dependencies`). JS runtime solvers in settings expect a Node-style runtime or are disabled.
